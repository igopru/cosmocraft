# CosmoCraft Designer — Техническая документация

## Обзор

**CosmoCraft Designer** — это веб-инструмент для визуального проектирования космических станций и кораблей в стиле воксельной графики. Позволяет пользователям создавать, редактировать, сохранять и загружать чертежи с последующим использованием в основной игре.

### Возможности

- 🛠️ **Три режима работы:** Строительство, Удаление, Покраска
- 🚀 **Сохранение кораблей** в папку `players/ID_USER/plane/`
- 🛰️ **Сохранение станций** в папку `players/ID_USER/station/`
- 💾 **Локальное сохранение** чертежей на диск пользователя
- 🎨 **14 типов вокселей** с цветовыми подписями
- 📊 **Характеристики:** энергия, щиты, груз, вооружение, стоимость

## Формат файла чертежа

Файлы чертежей хранятся в формате JSON со следующей структурой:

```json
{
  "name": "MyStation",
  "version": "1.0",
  "createdAt": "2026-03-08T12:00:00.000Z",
  "gridSize": 64,
  "voxelCount": 63,
  "voxels": [
    {
      "x": 28,
      "y": 32,
      "z": 30,
      "type": "turret_mount"
    },
    {
      "x": 30,
      "y": 32,
      "z": 27,
      "type": "thruster"
    }
  ]
}
```

### Поля объекта чертежа

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | string | Название модели |
| `version` | string | Версия формата чертежа |
| `createdAt` | string (ISO 8601) | Дата и время создания |
| `gridSize` | number | Размер сетки (по умолчанию 64) |
| `voxelCount` | number | Количество вокселей |
| `voxels` | array | Массив объектов вокселей |

### Поля объекта вокселя

| Поле | Тип | Описание |
|------|-----|----------|
| `x` | number | Координата X в сетке (0-63) |
| `y` | number | Координата Y в сетке (0-63) |
| `z` | number | Координата Z в сетке (0-63) |
| `type` | string | Тип вокселя (см. таблицу ниже) |

### Типы вокселей

| Тип | Описание | Цвет (hex) |
|-----|----------|------------|
| `hull_light` | Лёгкий корпус | #888888 |
| `hull_medium` | Средний корпус | #666666 |
| `hull_heavy` | Тяжёлый корпус | #444444 |
| `hull_reinforced` | Усиленный корпус | #222222 |
| `solar_panel` | Солнечная панель | #44aaff |
| `battery` | Аккумулятор | #ffaa44 |
| `shield_gen` | Генератор щита | #44ffaa |
| `thruster` | Двигатель | #ff4444 |
| `cargo_bay` | Грузовой отсек | #aa8844 |
| `turret_mount` | Крепление турели | #aa44ff |

| `window` | Окно | #aaddff |
| `light` | Свет | #ffffaa |

## API Reference

### API для кораблей

#### POST `/api/ships`

Сохраняет новый корабль в папку `players/{ID}/plane/`.

**Request Body:**
```json
{
  "name": "MyShip",
  "data": {
    "name": "MyShip",
    "version": "1.0",
    "voxels": [...],
    "voxelCount": 42
  },
  "playerName": "Gora"
}
```

**Response (200 OK):**
```json
{
  "success": true,
  "filename": "MyShip.blueprint.json",
  "path": "plane"
}
```

**Response (409 Conflict):**
```json
{
  "error": "Корабль с таким именем уже существует",
  "exists": true
}
```

#### PUT `/api/ships/:name`

Обновляет существующий корабль.

**Параметры:**
- `name` (path) — название корабля

**Request Body:**
```json
{
  "data": {
    "voxels": [...]
  },
  "playerName": "Gora"
}
```

**Response (200 OK):**
```json
{
  "success": true
}
```

**Response (404 Not Found):**
```json
{
  "error": "Корабль не найден"
}
```

### API для станций

#### GET `/api/stations`

Возвращает список всех сохранённых моделей (личные + общие).

**Query Parameters:**
- `playerName` (query) — имя игрока (по умолчанию: 'default')

**Response:**
```json
{
  "personal": [
    { "name": "MyStation", "type": "personal" }
  ],
  "shared": [
    { "name": "PublicStation", "type": "shared" }
  ],
  "all": [...]
}
```

#### GET `/api/stations/:name`

Возвращает данные конкретной модели.

**Параметры:**
- `name` (path) — название модели

**Query Parameters:**
- `playerName` (query) — имя игрока

**Response:**
```json
{
  "name": "MyStation",
  "version": "1.0",
  "voxels": [...]
}
```

#### POST `/api/stations/save`

Сохраняет новую станцию в папку `players/{ID}/station/`.

**Request Body:**
```json
{
  "name": "MyStation",
  "data": {
    "name": "MyStation",
    "version": "1.0",
    "voxels": [...],
    "voxelCount": 63
  },
  "playerName": "Gora"
}
```

**Response (200 OK):**
```json
{
  "success": true,
  "filename": "MyStation.blueprint.json",
  "path": "station"
}
```

**Response (409 Conflict):**
```json
{
  "error": "Станция с таким именем уже существует",
  "exists": true
}
```

#### PUT `/api/stations/save/:name`

Обновляет существующую станцию.

**Параметры:**
- `name` (path) — название станции

**Request Body:**
```json
{
  "data": {
    "voxels": [...]
  },
  "playerName": "Gora"
}
```

**Response (200 OK):**
```json
{
  "success": true
}
```

#### DELETE `/api/stations/:name`

Удаляет модель с сервера.

**Параметры:**
- `name` (path) — название модели

**Response (200 OK):**
```json
{
  "success": true
}
```

## Классы и интерфейсы

### DesignerScene

Основной класс конструктора, управляет Three.js сценой.

**Свойства:**
- `scene: THREE.Scene` — 3D сцена
- `camera: THREE.PerspectiveCamera` — камера
- `renderer: THREE.WebGLRenderer` — рендерер
- `grid: Voxel[][][]` — 3D массив вокселей (64×64×64)
- `currentVoxelType: VoxelType` — текущий выбранный тип вокселя
- `buildMode: 'place' | 'remove' | 'paint'` — текущий режим работы
- `voxelSize: number` — размер вокселя (8 единиц)

**Публичные методы:**

| Метод | Описание |
|-------|----------|
| `exportBlueprint(name: string): any` | Экспортирует текущую постройку в JSON |
| `importBlueprint(data: any): void` | Импортирует чертеж из JSON данных |
| `clearGrid(): void` | Очищает всю сетку вокселей |
| `setCurrentVoxelType(type: string): void` | Устанавливает текущий тип вокселя |
| `setBuildMode(mode: 'place' | 'remove' | 'paint'): void` | Устанавливает режим работы |

### StationManager (игра)

Менеджер станций в основной игре.

**Свойства:**
- `scene: THREE.Scene` — ссылка на сцену игры
- `stations: Map<string, THREE.Group>` — загруженные станции

**Публичные методы:**

| Метод | Описание |
|-------|----------|
| `loadStationList(): Promise<string[]>` | Загружает список моделей с сервера |
| `placeStation(filename: string, position: Vector3): Promise<boolean>` | Размещает станцию на сцене |
| `removeStation(name: string): boolean` | Удаляет станцию со сцены |
| `clearAllStations(): void` | Очищает все станции со сцены |

## Алгоритмы

### Размещение вокселя (placeVoxel)

```typescript
1. Получить координаты мыши в нормализованных координатах (-1 до 1)
2. Пустить луч (Raycaster) из камеры через точку мыши
3. Найти пересечение с существующими вокселями или плоскостью Y=0
4. Вычислить нормаль поверхности пересечения
5. Смещаться на 1 воксель вдоль нормали
6. Округлить координаты до сетки: gridX = Math.round(x / voxelSize)
7. Проверить границы сетки (0-63)
8. Проверить, что место свободно
9. Создать Voxel и добавить в сцену и grid массив
```

### Удаление вокселя (removeVoxel)

```typescript
1. Получить координаты мыши
2. Пустить луч, найти пересечение с вокселем
3. Преобразовать мировые координаты в индексы сетки
4. Проверить границы
5. Удалить mesh из сцены
6. Очистить ссылку в grid массиве
7. Вызвать dispose() для освобождения памяти
```

### Импорт чертежа (importBlueprint)

```typescript
1. Очистить текущую сетку (clearGrid)
2. Найти минимальные и максимальные координаты вокселей
3. Вычислить центр модели: centerX = (minX + maxX) / 2
4. Вычислить смещение для центрирования: offsetX = gridSize/2 - centerX
5. Для каждого вокселя:
   a. Применить смещение: newX = voxel.x + offsetX
   b. Проверить границы сетки
   c. Создать Voxel с мировыми координатами: worldX = newX * voxelSize
   d. Добавить в сцену и grid массив
```

## Взаимодействие с пользователем

### Горячие клавиши

| Клавиша | Действие |
|---------|----------|
| `1-9` | Выбор типа вокселя (по индексу в палитре) |
| `R` | Вращение (не реализовано) |
| `Ctrl+Z` | Отменить последнее действие |
| `Ctrl+Y` | Вернуть отменённое действие |
| `Пробел` | Циклическая смена режима (place → remove → paint) |
| `ЛКМ` | Поставить воксель / Удалить / Покрасить |
| `ПКМ` | Быстрое удаление вокселя |

### Режимы работы

1. **Строительство (place)** — установка новых вокселей
2. **Удаление (remove)** — удаление существующих вокселей
3. **Покраска (paint)** — изменение цвета существующих вокселей

## Поток данных

### Сохранение корабля

```
1. Пользователь нажимает "🚀 Сохранить корабль"
2. main.ts запрашивает название корабля через prompt()
3. designer.exportBlueprint() экспортирует данные постройки
4. Получение playerName из localStorage.getItem('playerName')
5. Отправляется POST /api/ships с {name, data, playerName}
6. Сервер получает или создаёт игрока через PlayerManager
7. Сервер создаёт папку players/{ID}/plane/ если не существует
8. Проверка на существование файла с таким именем
9. Если существует (409) — предлагается перезапись
10. Сохранение в players/{ID}/plane/{name}.blueprint.json
```

### Сохранение станции

```
1. Пользователь нажимает "🛰️ Сохранить станцию"
2. main.ts запрашивает название станции через prompt()
3. designer.exportBlueprint() экспортирует данные постройки
4. Получение playerName из localStorage.getItem('playerName')
5. Отправляется POST /api/stations/save с {name, data, playerName}
6. Сервер получает или создаёт игрока через PlayerManager
7. Сервер создаёт папку players/{ID}/station/ если не существует
8. Проверка на существование файла с таким именем
9. Если существует (409) — предлагается перезапись
10. Сохранение в players/{ID}/station/{name}.blueprint.json
```

### Локальное сохранение чертежа

```
1. Пользователь нажимает "💾 Сохранить локально"
2. main.ts запрашивает название чертежа
3. designer.exportBlueprint() экспортирует данные
4. Создаётся Blob с JSON данными
5. Создаётся временная URL ссылка
6. Автоматическое скачивание файла {name}.blueprint.json
7. Очистка URL после скачивания
```

### Загрузка модели в игре

```
1. Пользователь входит в игру
2. Вызывается game.showStationMenu()
3. StationManager.loadStationList() делает GET /api/stations
4. Сервер читает папку players/{ID}/, возвращает список файлов
5. Для каждого файла создаётся UI элемент с кнопками
6. При нажатии "Разместить":
   a. GET /api/stations/:name?playerName={name} для получения данных
   b. Парсинг JSON чертежа
   c. Создание THREE.Group для станции
   d. Для каждого вокселя создание THREE.Mesh
   e. Добавление группы на сцену в позицию перед камерой
```

## Обработка ошибок

### На клиенте

- **Ошибка загрузки модуля:** Проверка `window.addEventListener('error')`
- **Неверный формат JSON:** `try/catch` в `FileReader.onload`
- **Отсутствие дизайнера:** Проверка `if (!designer) return`

### На сервере

- **Файл не найден:** HTTP 404
- **Модель существует:** HTTP 409 Conflict
- **Ошибка записи:** HTTP 500 Internal Server Error
- **Неверные данные:** HTTP 400 Bad Request

## Безопасность

### Текущие ограничения

1. **Нет аутентификации** — любой пользователь может удалить любую модель
2. **Нет валидации имени** — возможны коллизии имён
3. **Нет ограничения размера** — можно загрузить огромный файл
4. **Нет санитизации пути** — потенциальная уязвимость path traversal

### Рекомендации для продакшена

1. Добавить JWT аутентификацию
2. Валидировать имя модели: `/^[a-zA-Z0-9_-]{3,32}$/`
3. Ограничить размер файла: `app.use(express.json({ limit: '1mb' }))`
4. Использовать `path.basename()` для санитизации имён файлов
